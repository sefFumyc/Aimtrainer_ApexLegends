# Spec: Godot 瞄准训练器 v1（引擎重写）

Status: ready-for-agent

术语以仓库根目录 `CONTEXT.md` 为准；实现决策以 `docs/adr/0001-0013` 为准。本 spec 不重复它们的全部内容，只做综合与排期。

四个切片各自对应一张实现票，见 `issues/01-04`。

## Problem Statement

现有的瞄准训练器是一个网页应用（TypeScript + Three.js）。网页这个载体的代价已经很具体：

- **输入延迟被显示器刷新率框死**。浏览器的 Gamepad API 只随 rAF 交付手柄数据，手柄固件报 1000Hz 也只能按 ~16.7ms 一档拿到。为此必须额外维护一个 C# XInput 伴生进程、ViGEm 虚拟手柄、WebSocket 输入源，以及一整套端到端延迟测量。
- **按键被浏览器抢占**。Ctrl（蹲伏）与 Ctrl+W 会关标签页，只能靠一个 C# WebView2 启动壳 + 禁用浏览器加速键才敢把 Ctrl 还给蹲伏。
- **美术与渲染要手写**。画面质量、后处理、命中提示、HUD 全部由 Three.js 手搓，风格化 PBR 的上限受制于自己写的着色器。
- **引擎能力全都要自己造**。碰撞、动画、音频、场景管理、编辑器可视化都不存在。

同时，这个项目最值钱的东西——**移植自 Apex 的移动手感模型**与**一整套瞄准训练调参手段**——是纯数学与状态机，与网页载体无关，本可以脱离浏览器独立存在。

## Solution

用 **Godot 4.7.2-stable + 纯 GDScript** 重写同一款瞄准训练器，跑在桌面上。移动手感与全部调参语义 1:1 保留；网页载体带来的问题（伴生进程、延迟测量、浏览器锁定、手搓渲染）连同它们的前提一起消失。

玩家得到的东西不变：一个半径 1000 的圆形场地，一个与玩家共用同一套移动模型的移动靶，两把枪，一套会实时告诉玩家"这一枪中了没"的 HUD，以及一个能把自己调好的参数存成命名的预设、并按计时分段自动调整靶子体型的训练循环。

新增的东西只有一件：**场地里会出现可切换的遮挡物**，且遮挡物真的参与碰撞与视线判定。

## User Stories

### 移动

1. 作为玩家，我想要在按下 W/A/S/D 时按 Apex 实测的速度曲线加速与转向，这样我的肌肉记忆能直接迁移过来，而不是重新学一套手感。
2. 作为玩家，我想要在松开方向键后按固定斜率（≈1425 u/s²）减速而不是瞬间停住，这样急停节奏可预测。
3. 作为玩家，我想要在 90° 换向时速度掉到 65%、180° 掉到 5%，这样"甩枪+反向跑"的代价与 Apex 一致。
4. 作为玩家，我想要在转动镜头时速度不瞬间跟着镜头吸附，而是经转向衰减收敛，这样转视角不会变成隐形的加速技巧。
5. 作为玩家，我想要按住 Shift 进入疾跑（目标 299 u/s）且只在前进半球生效，这样侧向与后退不能用来逃逸。
6. 作为玩家，我想要在空中用空气控制（≤6 rad/s 限速、速度大小不变）微调方向，这样跳跃中的转向是可控但不瞬变的。
7. 作为玩家，我想要在没有移动输入时沿原方向抛出（无输入惯性），这样跳出去不会被空气刹停。
8. 作为玩家，我想要在疾跑中按蹲触发滑铲（初速 ×1.53、以 ≈210 u/s² 减速），这样滑铲是位移手段而非装饰。
9. 作为玩家，我想要在滑铲中按跳得到按当前速度换算的额外水平加成，这样铲跳是值得练的技巧。
10. 作为玩家，我想要蹲伏行走（92 u/s）没有转向衰减，这样蹲着换向的响应是恒定的。
11. 作为玩家，我想要开镜时移速封顶降到 130.1 u/s，这样开镜是一个真实的位移取舍。
12. 作为玩家，我想要移动模拟按固定子步推进，这样我在 60Hz 与 144Hz 下走出的轨迹完全一致。

### 场地与遮挡

13. 作为玩家，我想要场地边界是半径 1000 的圆，这样靶子的活动空间与原版一致。
14. 作为玩家，我想要场地里有箱体与柱体构成的遮挡物，这样我可以练"利用掩体"而不只是空旷场对枪。
15. 作为玩家，我想要遮挡物实体阻挡我，这样掩体是有位置的、不能穿过去。
16. 作为玩家，我想要在设置里切换「场地布局」（空旷 / 少量遮挡 / 多遮挡），这样我能在不同难度下对比自己的表现。
17. 作为玩家，我想要遮挡物不生成在我的出生点与靶子的刷新点附近，这样我不会一开局就卡在柱子里。

### 武器与命中

18. 作为玩家，我想要开局手持步枪（连射 10 发/秒、身体 25 / 爆头 35），这样我能立刻开始练习。
19. 作为玩家，我想要按 1 / 2 直接选枪、按 Q 在手柄上就近切换，这样切枪不需要看说明书。
20. 作为玩家，我想要手枪是单发（最快 3 发/秒、身体 70 / 爆头 110），且冷却期内的点击会被缓冲一发，这样手枪的节奏是"点得准"而不是"点得快"。
21. 作为玩家，我想要按住右键进入开镜（视野 92.35°→76.64°、开镜 0.22s / 退镜 0.088s），这样开镜的过程本身是可感知的。
22. 作为玩家，我想要开镜时视角灵敏度可单独设定倍率，这样我能按自己的习惯配开镜手感，同时不改变开镜移速。
23. 作为玩家，我想要命中头部按武器各自的爆头数值结算伤害（步枪 35、手枪 110，不是身体伤害的固定倍数），这样爆头是有意义的。
24. 作为玩家，我想要子弹被遮挡物挡住，这样躲在掩体后面的靶子打不到，掩体是双向的。
25. 作为玩家，我想要在第一人称看到自己的双臂与枪，且贴到柱子时枪不会插进柱子里，这样掩体边缘的贴墙作战观感不崩坏。

### HUD 与反馈

26. 作为玩家，我想要屏幕中心有一个固定的实心圆点准星，这样我总有一个瞄准参照。
27. 作为玩家，我想要命中时准星位闪出白色 X 并保持 250ms，这样"这一枪中了"是一眼可读的。
28. 作为玩家，我想要击杀时闪出更大的红色 X 并保持 480ms，且击杀提示不会被后续命中打断，这样击杀与命中不会混淆。
29. 作为玩家，我想要 HUD 实时显示命中/总射与准确率，这样我不必等到结算才知道自己今天的准度。
30. 作为玩家，我想要 HUD 显示我的血量与靶子的血量，这样我知道双方还剩多少。
31. 作为玩家，我想要 HUD 显示击杀数与计时，这样我知道自己练了多久、拿了多少分。
32. 作为玩家，我想要每次开火有枪声、命中/击杀有不同音高的反馈音，这样听觉能补上视觉延迟。
33. 作为玩家，我想要枪口火光与曳光弹可单独开关，这样我能按需在"反馈丰富"与"画面干净"之间选。

### 对局

34. 作为玩家，我想要双方血量各 600、靶子死亡 1.5s 后在我的视线前方刷新，这样对局能无尽延续。
35. 作为玩家，我想要我的血量归零后满血复活而不是结束对局，这样练习不会被打断。
36. 作为玩家，我想要击杀靶子立即回满血，这样连杀有正反馈。
37. 作为玩家，我想要可选开启吸血（按本次伤害回血、封顶 600），这样我能用另一种方式维持练习。
38. 作为玩家，我想要按 ESC 结束当前对局并看到结算（准确率、击杀、死亡、用时），这样我能记录一段练习。
39. 作为玩家，我想要复活点落在靶子的视线锥之外且不在遮挡物里，这样我不会一复活就被打或卡住。

### 靶子的行为

40. 作为玩家，我想要靶子与我共用同一套移动模型，这样它的移动是"人能做到的"而不是另一套物理。
41. 作为玩家，我想要靶子持续侧移、没有静止空窗，这样练枪时目标不会站着不动。
42. 作为玩家，我想要靶子的变向不规律（每次从当前模式区间重抽），这样我不能靠背节奏预瞄。
43. 作为玩家，我想要能分别设定长/中/快三档横移的权重，这样我能练不同节奏的目标。
44. 作为玩家，我想要能设定模式切换的间隔上下限，这样我能控制节奏变化的剧烈程度。
45. 作为玩家，我想要能设定靶子被命中时立刻翻向的概率（连发/单发两档分开），这样我能练"打移动目标"而不只是"打会翻的目标"。
46. 作为玩家，我想要能设定两次变向之间的最小间隔，这样靶子不会因为挨打而把自己钉在原地。
47. 作为玩家，我想要能设定靶子与我的目标距离（默认 120）与死区带，这样我能练不同距离的枪。
48. 作为玩家，我想要能选靶子的进退模式（保持距离 / 动态游走），这样我能练单一的定距靶或更自然的走位。
49. 作为玩家，我想要能设定动态游走的前压/后退倾向，这样我能练靶子主动逼近或拉开的情形。
50. 作为玩家，我想要能设定靶子的体型半径（4–60，默认 8），这样我能从"大靶子"逐步练到"小靶子"。
51. 作为玩家，我想要可选择让靶子常驻开镜（只体现为移速变慢），这样我能练打慢速目标。
52. 作为玩家，我想要靶子会绕开遮挡物而不是撞上去卡住，这样掩体场地里靶子仍然是持续移动的。
53. 作为玩家，我想要靶子隔着遮挡物时不开火，这样掩体在"对枪"这件事上也是有效的。
54. 作为玩家，我想要靶子开火是一个可开关的选项，这样我能在纯瞄靶与对枪之间切换。
55. 作为玩家，我想要能设定靶子每发的命中概率（0–100，默认 68），这样"挨打"的量是我自己能定的。
56. 作为玩家，我想要靶子被我瞄上 350ms 后才开始开火、且被我打中时会立刻还手，这样对枪有来有回而不是被动挨打。

### 训练循环

57. 作为玩家，我想要可选开启间隔计时器，这样我能用"准备段 → 游玩段 → 休息段"的循环练，而不是无节制地一直打。
58. 作为玩家，我想要准备段有 5 秒大字倒计时与逐秒预哔，这样我有时间把手放回键鼠。
59. 作为玩家，我想要休息段显示剩余秒数与本轮战绩，这样休息时我能复盘。
60. 作为玩家，我想要休息段不可跳过、只有 ESC 能退出整个会话，这样计时会话的节奏是可信的。
61. 作为玩家，我想要可选开启自动调径（按每段准确率自动调小/调大靶子体型），这样难度会跟着我的水平走。
62. 作为玩家，我想要看到每段"半径 旧→新"的记录，这样我知道自动调径到底做了什么。

### 设置与预设

63. 作为玩家，我想要能分别设定鼠标与手柄灵敏度，这样两套设备的视角手感都能配。
64. 作为玩家，我想要设置分「目标与 bot」「躲避与移动」等页面而不是一长条，这样我能快速找到要调的项。
65. 作为玩家，我想要把 19 项训练参数存成命名预设，这样我能为不同的练习课切换整套配置。
66. 作为玩家，我想要在选中预设后的一切改动自动写回该预设，这样我不需要额外点保存、也不会切走再切回丢进度。
67. 作为玩家，我想要"不选预设"这个状态就是全局设置本身，这样不折腾预设的人的行为与没有预设时完全一致。
68. 作为玩家，我想要设置改动立即生效并持久化、重启不丢，这样调参是零摩擦的。
69. 作为玩家，我想要画面质量有低/中两档，这样我能在低配机器上换帧率。

### 输入

70. 作为玩家，我想要有手柄连接时只接受手柄输入、没有手柄时只接受键鼠，这样我不会因为手柄漂移而莫名其妙地移动。
71. 作为玩家，我想要左摇杆按 8 向离散并带每轴 13% 死区，这样手柄移动是可复现的定速而不是线性推杆。
72. 作为玩家，我想要左摇杆前推超阈值自动疾跑，这样我不用在手柄上额外按一个 sprint 键。
73. 作为玩家，我想要右摇杆 0 死区，这样视角没有任何钳制。
74. 作为玩家，我想要蹲伏能绑在 Ctrl 与 C 两个键上，这样两种习惯都能用。

### 工程（非玩家可感）

75. 作为开发者，我想要可移植的纯逻辑（移动积分、躲避控制、单发缓冲、计时器、对局统计）不依赖节点树，这样这些模块能脱离引擎单独推理与验证。
76. 作为开发者，我想要实体与组件以场景表达，这样这个仓库能直接当 FPS 模板复用。
77. 作为开发者，我想要全局设置由一个单例承载并持久化到用户目录，这样任何模块都能读到当前设置而不必层层传参。
78. 作为开发者，我想要第三方美术各自带许可说明文件，这样 CC0 的来源与边界是留痕的。

## Implementation Decisions

### 引擎与语言

Godot **4.7.2-stable** + 纯 GDScript，不引入 .NET。4.5/4.6 已停止维护，4.8 仅有 dev 快照，不存在 Godot 5。（ADR-0001）

### 移动模型

`CharacterBody3D` 只用来做碰撞求解（`move_and_slide()`）；**`velocity` 全部由脚本自己算**，按固定子步做分段线性积分，与参考实现同构。不使用 Godot 的默认加速与摩擦。转向衰减、速度保留率（`cos(θ/2)^1.2`）、速度修正器（持枪 0.87 / 开镜 0.652）、滑铲、滑铲跳跃、蹲伏、空气控制全部按参考实现移植。（ADR-0002）

### 输入

只用 Godot InputMap + 原生手柄读取。**整条伴生输入链路与「输入延迟与测量」领域概念一并删除**（C# XInput 进程、ViGEm 虚拟手柄、WebSocket 输入源、Web Worker 隔离、端到端延迟测量）。保留输入独占、摇杆离散、两杆独立死区、开镜灵敏度倍率的统一乘子。（ADR-0003）

键位：WASD 移动、Space 跳、Shift 疾跑、Ctrl 或 C 蹲、左键开火、右键开镜、1/2 选枪、Q（手柄 Y）就近切枪。**移除**空手状态与 B 键长按双义。（ADR-0010）

### 场地

边界是圆心在原点、**半径 1000 的圆**，径向判定（Bot 的「撞墙反向」「贴墙内拐」依赖它）。视觉为程序化地面 + 环形围墙，不搬原版竞技场看台。遮挡物为程序化箱体与柱体，**参与碰撞且参与射线**。三档「场地布局」设置项（空旷 / 少量遮挡 / 多遮挡，默认少量遮挡）同时驱动 Bot 的前向探测阈值。生成时避开玩家与 Bot 的刷新点。（ADR-0004）

### 靶子（Bot）

**不引入寻路**。保留「直线侧移 + 撞墙反向」模型，额外加一条**前向探测**：探到遮挡物或边界时提前触发变向，复用「撞墙反向」的优惠语义（只翻方向、不重掷前后分量、不重置变向/切换计时，但重置「最短躲避时间」时钟）。躲避控制的全部语义（三档横移、模式权重、走廊、前后分量）零改动。（ADR-0005）

开火新增**视线判定**：被遮挡物阻断则本发不开火（不掷骰、不消耗随机数）。命中仍由「命中率」概率掷骰决定——「能不能开枪」与「打得准不准」是刻意分开的两件事。（ADR-0006）

### 武器模型隔离

用 `SubViewportContainer` + `SubViewport`（透明背景）+ 独立武器相机 + `RemoteTransform3D` 跟随主相机，cull mask 把武器几何隔离到独立视觉层。理由：场地有遮挡物，贴柱子时单相机方案会让枪穿模。（ADR-0008）

回退点：若实测帧率不达标，改单相机 + 视觉层隔离，同时放宽 CONTEXT 里 Viewmodel 词条「不被穿透」的承诺。

### 项目结构与持久化

三层：实体与组件用 `.tscn` 场景；可移植纯逻辑写成**不依赖节点树**的逻辑类，由场景调用；全局设置用 Autoload 单例承载，持久化到用户目录配置文件（替代 localStorage）。注意参考实现里的设置持久化按「网址源」隔离，这个语义随载体一起消失。（ADR-0009）

### 美术与音频

美术全部 CC0：枪械用 Kenney Blaster Kit，角色与动画用 KayKit Adventurers。各自附许可说明文件入库。（ADR-0007）

音频改为构建期按参考实现的包络与频率（155Hz 枪声 / 200Hz 击中 / 660Hz 预哔 / 990Hz 开始哔，约 30ms、4ms 缓起音、陡衰减、无噪声瞬态）生成短音资产入库；±5% 音高微差用播放器的音高缩放实现，不预生成变体。不使用 `AudioStreamGenerator` 运行时合成。（ADR-0012）

### 渲染与后处理

Forward+ 渲染器，桌面 Windows。后处理全部用引擎内建的 `WorldEnvironment`（色调映射、Glow、SSAO/SSIL、SSR、体积雾、Auto Exposure、Adjustments）。「画面质量」两档映射到后处理开关与阴影精度，不用逐节点 Environment 硬编码。

注意：SDFGI/SSIL/体积雾是性能大户，训练器追求高帧率，低档默认全关。

### 交付切片

1. **切片一（本 spec 的交付目标）**：圆形场地（含可切换遮挡物）+ 玩家移动（完整速度曲线 / 滑铲 / 蹲伏 / 跳跃 / ADS）+ 步枪与手枪 + 靶（命中判定与爆头）+ 基础 HUD（准星 / 击中提示 / 准确率 / 血条 / 击杀）。
2. **切片二**：靶子的完整 AI（躲避控制 + 前向探测 + 概率命中 + 视线判定 + 开火门控）。

## Testing Decisions

引入 **GUT**，只在**一个高缝**上做行为测试：不依赖节点树的纯逻辑类。（ADR-0013 取代了 ADR-0011 的「不写自动化测试」；ADR-0011 的「文档优先」与「垂直切片」仍有效。）

### 被测模块（按价值排序）

1. **移动积分**（最优先）。它是整个项目的底座，全部参数是从 Apex 实测值移植来的，任何一处回归都会直接毁掉核心资产——肉眼看曲线看不出「90° 换向后该保留 65% 还是 71%」。断言：给定控制意图与 dt 序列后的速度向量轨迹、90° 换向速度保留率、松手减速到 0 的时长、滑铲初速倍率（×1.53）、滑铲跳跃倍率、空中速度上限 500 u/s、开镜速度封顶 130.1 u/s、多轴合并后的钳制值。
2. **躲避控制**。断言：给定随机源与经过时间后的变向序列与间隔落在模式区间内、最短躲避时间内掷中的躲避被丢弃、撞墙反向不重置变向计时但重置「最短躲避时间」时钟。
3. **单发缓冲**。断言：冷却期内的多次点击只缓冲一发、切枪重置缓冲。
4. **计时器阶段机**。断言：「准备→游玩→休息→…→最终结算」无尾休息、休息不可跳过。
5. **对局统计**。断言：准确率口径在实时与结算快照下一致、击杀回满不溢出。

切片一只需要第 1 项（连同 GUT 接入本身）；第 2–5 项分别落在切片二与切片三。

### 测试的写法

- 只断言**外部行为**（给定输入与时间，断言可观测的输出），不断言内部状态字段、私有方法与实现细节。
- 不依赖节点树、不启动场景、不需要渲染设备与输入设备——纯逻辑类可直接构造。
- 参考实现里已有对应的测试文件可作为先例（移动曲线、躲避控制、Bot 概率、单发、计时器、对局各有一份）；移植它们的**断言**比从零设计便宜，但**不移植其测试代码结构**（那是网页时代的模块边界）。

### 明确不测的东西

场景装配、节点树布线、渲染与后处理、viewmodel 的 SubViewport 隔离、InputMap 映射、帧率、手感、观感、输入延迟——这些只能实测，断言不了。

## Out of Scope

- **靶子 AI 的完整行为**（切片二）。切片一只需要靶子能被命中、能被打死、能复活。
- **训练器功能面**（切片三）：间隔计时器、预设、自动调径、设置面板的完整页面。
- **角色动画与特效**（切片四）。
- **原版的竞技场看台视觉**（原 ADR-0028）：换成程序化地面与环形围墙。
- **空手状态、B 键长按双义、F1–F3 调试面板**（原 ADR-0010 已移除）。
- **整条伴生输入链路与延迟测量**（原 ADR-0009/0011/0012/0013/0014/0015/0016/0024 所描述的机制）。
- **网页专用层**：指针锁、浏览器锁定、可拦边界、localStorage 与网址源隔离、WebView2 启动壳、Vite 开发服务器与端口清理脚本。
- **导出与分发**：本 spec 不含打包成可执行文件、图标、安装器。

## Further Notes

- **参考实现是只读参考，不是移植源**。它的代码结构属于网页时代，直接照搬会把浏览器时代的模块边界带进引擎项目。要移植的是**数值与语义**，不是文件。
- **移动参数是实测值，不是推导值**。任何"看起来应该更合理"的调整都会破坏与原版的手感对应关系；要改必须先说明这是有意的偏离，并记一条 ADR。
- **两项待办会落在切片一里**：(1) 下载并安装 Godot 4.7.2 做启动校验——该引擎需写到本仓库之外的路径，会突破沙箱限制；(2) 下载两个 CC0 资源包并入库（涉及仓库体积策略，需决定是否用 Git LFS）。
- **本 spec 的三条假设可能被证伪**：`SubViewport` 的帧率开销（ADR-0008 有回退点）、前向探测能否让靶子在多遮挡布局下不卡死（ADR-0005 的核心风险）、遮挡物是否真的改善而非干扰瞄准训练（这是玩法判断，只能靠玩）。
