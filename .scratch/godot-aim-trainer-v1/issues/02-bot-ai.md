# 02 — 切片二：靶子的完整 AI

Status: done

对应 spec: `../spec.md`（切片二）。术语以 `CONTEXT.md` 为准，决策以 `docs/adr/0005`、`0006` 为准。依赖票 01。

## 目标

把切片一里那个「能被命中的受击体」变成**会动的对手**：持续侧移、不规律变向、会绕开遮挡物、会隔着掩体停火、会按概率打中玩家。

## 范围

### 1. 躲避控制（零改动移植）

- 三档横移：长 / 中 / 快，时长区间 0.6–1.0 / 0.4–0.7 / 0.2–0.5s；模式权重 0.3 / 0.4 / 0.3。
- 每次变向从当前模式区间**重抽**，不背节奏。
- 「最短躲避时间」（默认 0.15s）：该时钟内掷中的躲避被丢弃。
- 走廊与前后分量语义原样保留。

### 2. 移动与撞墙

- 靶子与玩家**共用同一套移动模型**（切片一的纯逻辑类），它的移动是「人能做到的」。
- 保留「直线侧移 + 径向撞墙反向」：撞到半径 1000 边界时只翻方向，**不重掷前后分量、不重置变向与切换计时**，但**重置「最短躲避时间」时钟**。
- 新增**前向探测**：探到遮挡物或边界时**提前**触发变向，复用上述撞墙反向的优惠语义。（ADR-0005）
- **不引入寻路。**
- 前向探测阈值由「场地布局」档位驱动。

### 3. 视线判定与开火门控

- 被遮挡物阻断视线时本发**不开火**——不掷骰、不消耗随机数。（ADR-0006）
- 「能不能开枪」与「打得准不准」刻意分开：能不能开枪看视线，打得准不准仍由命中率概率掷骰决定。
- 开火前置门控：被玩家瞄上连续 350ms 后才开始开火（瞄准视锥 20°）；被玩家打中时立刻还手（受击反击）；攻击锁定语义保留。
- 命中率由设置项决定（0–100，默认 68）。
- 开火本身是**可开关**的选项，关掉后靶子只是移动靶。

### 4. 靶子侧设置项

- 三档横移权重、模式切换间隔上下限、受击翻向概率（连发 0.1 / 单发 0.4 两档分开）、最短躲避时间。
- 与玩家的目标距离（默认 120）与死区带；进退模式（保持距离 / 动态游走）；动态游走的前压 / 后退倾向。
- 体型半径（4–60，默认 8）、常驻开镜（只体现为移速变慢）。
- 靶子血量与刷新已由票 01 承担，本票只补「刷新点落在遮挡物之外且不在玩家当前视线锥里」。

## 验收条件

1. 靶子持续侧移，**没有静止空窗**。
2. 变向间隔落在当前模式区间内且不规律；把三档权重调到极端（如全快档）后节奏明显改变。
3. 在「多遮挡」布局下持续观察数分钟，靶子**不会卡在柱子上**，也不会贴着遮挡物抖动。
4. 靶子躲在遮挡物后面时不向玩家开火；视线一恢复即刻恢复开火。
5. 关掉靶子开火后，靶子只移动不攻击。
6. 把命中率设为 0 时玩家不会掉血；设为 100 时每次开火都掉血。
7. 靶子被玩家瞄上不足 350ms 前不开火；玩家打中它时会立刻还手。
8. 靶子死亡后的刷新点不在遮挡物里、不在玩家的视线锥内。
9. **躲避控制**有行为测试：给定随机源与经过时间，断言变向序列与间隔落在模式区间内、最短躲避时间内掷中的躲避被丢弃、撞墙反向不重置变向计时但重置最短躲避时间时钟。

## 依赖

- 票 **01**（移动纯逻辑类、遮挡物、场地半径、玩家受击与血量）。

## 备注

- 本票的核心风险：**前向探测能否让靶子在多遮挡布局下不卡死**。这是 spec 里三条可能被证伪的假设之一，只能靠实际跑观察。若证伪，回退方案是给靶子加一条最简障碍绕行（仍不走寻路）。
- 前向探测的阈值调不好会让靶子「提前变向」变成抖动来源；先按场地布局档位给粗值，靠观察收敛。

## Comments

**已实现**（三层分离，ADR-0009）：

- 纯逻辑：`src/logic/avoidance.gd`（三档横移 / 模式权重 / 变向重抽 / 最短躲避时间 / 撞墙反向 / 前后分量）、`src/logic/bot_ai.gd`（共用移动模型 + 距离保持与动态游走 + 贴墙内拐 + 前向探测 + 开火门控状态机）。
- 场景：`target.tscn` 由受击体改成 `CharacterBody3D`（`Target` 只做 AI 的碰撞载体与表现层）；`main.gd` 负责感知装配、bot 开火扣血 / 曳光 / 音效、玩家重生、刷新点抽样。
- 设置：`game_settings.gd` 增加 bot 侧设置并持久化，`settings_panel.gd` 加对应控件。

**验收 3（多遮挡下不卡柱、不抖动）的结论：原「命中体 = 模型部件盒」会让靶被柱角剐住。** KayKit 骑士是 T 字绑定姿势，剑与盾横向伸出约 40 单位，而探测射线只从身体中心发出——探不到身体边缘已经剐上的柱角，于是「纯逻辑满速、`move_and_slide()` 位移归零」原地卡死。修复见 ADR-0014：移动改由与玩家同构的胶囊承担（单独一层、不进任何射线 mask），命中体仍取模型部件盒挂在子 `StaticBody3D` 上；受阻翻向加 0.3s 承诺窗口与物理兜底 `on_blocked`；靶的推进从 `_process` 移到 `_physics_process`。

**顺带修掉的几何问题**：模型原先按「合并包围盒中心」做水平居中，而骑士 GLB 自带多套武器道具（4 面盾、3 把剑）向单侧伸出、把 AABB 中心拽偏，角色因此整体偏离逻辑原点约 20 单位（准星与骑士错位、移动碰撞体贴着空气）。模型原点本身就是角色脚下中心，改为只把脚底对到 `y=0`、不再水平居中。

**验证证据**：

- `godot --headless -s addons/gut/gut_cmdln.gd`：113 个用例 / 1008 断言全绿（其中 `test_bot_ai` 覆盖验收 1、2、4–7、9）。
- 临时驱动场景在「多遮挡 + 玩家在遮挡带内游走」下跑 3 次各 180s：**卡住事件 0/0/0**，最长近乎静止 0.07–0.17s；视线被遮挡帧占比 24–37%；LoS 对照、刷新点抽样（400 次不落遮挡、不落视线锥）、玩家重生点抽样、玩家开火射线命中靶（伤害 35 爆头）全部通过。
- 真实主场景 `--headless --quit-after 300` 启动零 ERROR / WARNING。临时验证脚本已删除。

**已知粗糙处**（不阻塞本票，留给后续）：

- 骑士 GLB 的 `Knight_Head` / `Knight_Helmet` 网格包围盒偏大（约占通高一半），瞄准胸口也会判成爆头；命中盒精度要更贴合需要单独收窄头部件盒。
- GLB 自带多套武器道具（都可见且重叠），命中盒随这些可见道具一起外扩——「所见即所中」成立，但判定的「身体」比视觉上的人形宽。
- 上述两条都属票 01 遗留的命中体几何精度，不影响本票的 AI 行为与验收。
