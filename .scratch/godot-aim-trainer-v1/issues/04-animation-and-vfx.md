# 04 — 切片四：角色动画与特效

Status: done

对应 spec: `../spec.md`（切片四）。术语以 `CONTEXT.md` 为准。依赖票 01、02。

## 目标

让靶子的移动「看起来是人在走」，让开火「看起来有枪口和弹道」。这一票**不动任何数值与判定**，只补表现层。

## 范围

### 1. 角色动画（靶子）

- 姿势混合：站立 / 蹲伏 / 滑铲等姿势之间的混合，切换时机与移动状态机对齐（状态是切片一和二已经算好的，本票只负责播）。
- 步态周期：按实际水平速度驱动步频，而不是按固定时间循环。
- 朝向侧偏：躯干在移动方向与瞄准方向之间做侧偏，而不是整体瞬转。
- 用 KayKit Adventurers（CC0）的骨骼与动作；用 `AnimationTree` / `AnimationPlayer` 组织。

### 2. 特效

- 枪口火光：开火瞬间在枪口位置播放，可单独开关。
- 曳光弹：从枪口到命中点的弹道表现，可单独开关。
- 脚底接触暗影：靶子脚下跟随的接触阴影。

## 验收条件

1. 靶子加速、减速、换向时步频随之变化，没有「原地滑步」。
2. 靶子从站立切到蹲伏、切到滑铲时姿势平滑过渡，不出现瞬间弹跳。
3. 靶子侧向移动且同时瞄准玩家时，躯干有明显的朝向侧偏。
4. 开火能看到枪口火光；关闭该设置项后不再出现。
5. 开火能看到曳光弹，且落点与命中点一致；关闭该设置项后不再出现。
6. 靶子脚下有跟随的接触暗影，不穿地不漂移。
7. 以上全部开关**不改变任何伤害、命中判定与移动数值**（对同一段输入回放，结果与未开特效时逐帧一致）。

- 票 **02**（靶子的移动与开火行为）。

## Comments

### 落点

- **姿势混合**（纯逻辑）`src/logic/pose_blend.gd`：语义移植参考实现 `render/poseBlend.ts` 的
  `PoseBlendController`。参考实现把权重摊成 idle / left / right 三分量，但引擎侧只消费
  `left − right` 这一个标量（侧偏），而「混合后的三分量之差」≡「三分量之差再混合」（线性），
  所以直接混合这一个标量，对外行为完全等价。保留 250 / 200 / 250 ms 三段过渡与「可随时打断、
  从当前侧偏续上」的语义。
- **步态周期**：`Frame.gait = 实际水平速度 ÷ 满速（BASE_SPEED × SPEED_MULT_GUN）`，场景把它
  写进 `AnimationPlayer.speed_scale`（静止动作不缩放，走动动作**纯等比例**、不设上下限——
  上下限会破坏 CONTEXT「随当前速率等比例放慢」，数值探针实测全程最大偏差 0.0000）。
  参考实现的正弦 bob **不移植**：KayKit 的动作本身是烘焙了位移的，两者叠加会变成双重运动。
- **朝向侧偏**（骨级）`src/scenes/pose_lean.gd`：骨盆朝移动方向 45°、胸腔相对骨盆 −30°
  合成世界肩偏 15°，头再反向 −15° 把继承来的肩偏抵消——世界净偏角归零，即 CONTEXT
  「肩膀同向 15°，**头不动（≈0°）**」（数值取自参考实现 `render/character.ts` 的 `CharacterRig.apply`）。
- **动作选择**：直立按前后分量分 `Walking_A` / `Walking_Backwards`，侧走用
  `Running_Strafe_Left` / `Running_Strafe_Right`，静止用 `Idle`。必须播动作——Knight 是 T 字绑定，
  不播则双臂一直横伸。
- **脚底暗影**：程序化径向渐变（`GradientTexture2D` 放射填充）贴在地面上一层，不参与碰撞与射线，
  随「体型半径」的水平缩放一起变大。

### 为什么不移植 / 无法演示

- **手腕反旋 −15° 不移植**：靶子手里是 KayKit 的剑，而枪口是 `Target.MUZZLE_HEIGHT` 的固定偏移、
  不挂在骨骼上，没有需要被抵消的偏转。
- **验收 2（站立 → 蹲伏 → 滑铲的姿势过渡）无法演示**：`BotAi` 从不产生蹲伏 / 滑铲 / 跳跃状态
  （切片一、二的状态机里就没有），KayKit Adventurers 也没有对应的蹲伏 / 滑铲动作可播；
  参考实现的 `PoseBlendController` 本身同样只有 idle / left / right / straight 四类。
  纯逻辑的混合函数对「直立 ↔ 侧向」是结构性覆盖的，但这一条在靶子身上没有可观察的入口。
- **验收 4 / 5 在票 03 已实现**（枪口火光、曳光弹及各自开关），本票未改动，只做了回归验证。

### 一处实现取舍（重要）

侧偏**没有**用 `SkeletonModifier3D`（它本是引擎为「动画之后叠加程序化骨姿势」提供的分层）：
本机 4.7.2 上实测修饰器写入会被同一帧内随后应用的动画覆盖（读回恒为动画值，±45° 变 ~±2°）。
已排除的猜测：`process_priority`、`move_child` 调序、`callback_mode_process` 改物理帧，均无效；
而「帧间从外部写骨」能稳定活过整帧。故改为 `AnimationPlayer` 走 MANUAL、由
`Target._apply_pose` 手动 `advance(delta)` 后**紧接着**写骨——顺序由调用点自己保证，
不依赖引擎的进程顺序。细节与排除过程记在 `pose_lean.gd` 头注。

### 审查后的两处修正与一处遗漏修复

- **头骨反旋**（审查发现）：侧偏最初只写 hips / chest 两根骨，head 是 chest 的子节点会
  继承 15° 肩偏跟着歪——违反 CONTEXT「头不动（≈0°）」。已补 head −15° 反旋；满速实测
  本地骨姿 +45 / −30 / −15，世界合成 45 − 30 − 15 = 0，头始终朝瞄准方向。
- **步频钳制移除**（审查发现）：原 0.6–1.4 的 `speed_scale` 钳制是「看起来更合理」的调整，
  会破坏「随当前速率等比例放慢」（< 60% 满速时失真）。已删，改为纯等比例。
- **动作循环**（验收遗漏）：KayKit 的动作在 GLB 里按「不循环」导入
  （实测 `loop_mode == LOOP_NONE`），走一步（约 1.07s）就定格在最后一帧，恰好是
  验收 1 要排除的「原地滑步」。`_setup_animation` 运行时把本票播的五支动作逐个改成
  `LOOP_LINEAR`（不动资产导入设置）。

### 验收 7 的保证方式

表现层（`PoseBlend` / `PoseLean` / 暗影 / 火光 / 曳光）**只读** `BotAi.sim`，不写回位置、速度或朝向；
五个开关（枪口火光、曳光弹、命中提示、画面质量、暗影无开关）都不参与伤害、命中判定与移动积分。
逐帧一致性由结构保证，未另写回归脚本。

### 验证

- 新增 `tests/unit/test_pose_blend.gd`（15 例）：分类与阈值、侧偏符号表、步频归一化与钳制、
  250 / 200 / 250 ms 三段过渡、打断式过渡、直立↔直立只换语义不混合、`reset`、切换帧才报过渡时长。
- GUT 全量 142 tests / 1136 asserts 全绿（本票新增 15 例）。
- 真实主场景 headless 启动 240 帧零 ERROR / WARNING。
- 真实渲染截图确认：非 T 字站姿、走 / 侧走动作随运动切换、播放速率随速度变化、
  横移时骨盆 ±45° 与胸腔 ∓30°、脚底暗影贴地跟随（藏掉模型单拍一张确认）。
- 审查修正后的数值探针（真实主场景 10 秒物理帧）：动画位置回落 19 次（循环生效）、
  播放速率与归一化速度最大偏差 0.0000（等比例生效）、满速本地骨姿
  hips +45° / chest −30° / head −15°（头骨反旋生效，世界净偏角 0）。

### 附带修复：右摇杆转视角无响应

「手柄灵敏度」被按鼠标的 rad/px 量纲存成了 ~0.0022，而它实际是「对满推基准 2.5 rad/s 的无量纲倍率」，
于是满推只有 2.5 × 0.0022 ≈ 0.32°/s，看起来就是没反应。现恢复为倍率语义
（`GAMEPAD_SENSITIVITY_MIN/MAX/DEFAULT` = 0.2 / 5.0 / 1.0），并加旧值迁移守卫
（落在合法区间外的历史值一律丢弃、回落默认）+ 设置面板滑块改用新区间与 0.1 步进。
该键不在 `PresetStore.FIELDS` 内，改量纲不会污染预设。
