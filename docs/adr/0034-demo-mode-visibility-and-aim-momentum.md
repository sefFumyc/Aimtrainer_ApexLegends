# 演示模式的可见性门控与拉枪惯性

起因：ADR-0033 的演示模式里玩家**不能自己转视角**（视角已被脚本接管），相机永远在追 bot。于是 bot 一躲到「遮挡物」后面，准星仍死死咬着它、`on_target` 一真就开火——**子弹全打在掩体上**。用户要求：看不见 bot 时别按住开火、也别隔墙锁；正在进行的拉枪要带着惯性收住（不能像自瞄一样一帧静止），bot 重新可见后立刻再拉枪、瞄到位再开火。

**「看不见」的口径**：只算**几何遮挡**——玩家眼位到 bot 瞄准点（「命中体」地上段垂直中心，ADR-0033）的射线被「遮挡物」或「围墙」阻断。**不算「bot 不在画面 / FOV 内」**：演示模式下玩家无法自己转头、相机永远在追 bot，bot 几乎永远在画面中央；真正的「不在画面」只发生在相机正甩向它的那一小段，若把 FOV 也算进去，就会在最需要继续甩枪的那一刻把追踪掐掉、形成「永远追不回来」的死锁。判定用**单根射线射向瞄准点**：只露一条腿而躯干被挡时算「看不见」——因为此时锁躯干必然开火打掩体，与「别按住开火」自相矛盾；单点口径让「锁定」与「开火」**共用同一根射线**，只有一条规则。

**三态**：(1) **看得见** → 拉枪追踪 + 瞄到位开火（ADR-0033 原样）；(2) **看不见** → 不锁定（滑行）、不按住开火；(3) **bot 死亡空窗** → 原地冻结（ADR-0033 原样，**不改**）。

**死亡不滑行**：死亡瞬间仍是「一帧急停」，刻意与「看不见」区别对待——人类高手会预判对方死亡时间、直接停住，并不会滑行（用户裁定）；而「进入掩体时一点惯性都没有」才奇怪。两个态语义不同，用独立标志区分，不做统一。

**拉枪惯性（滑行）**：失去可见的那一刻，把**最后一帧的角速度继承下来**、按指数速率 **10 /s** 衰减到 0（方向不变；时间常数 0.1s，可见的滑行约 0.2–0.3s；滑出角度 = 结束时角速度 ÷ 10，典型 4°–15°）。刻意**不复用**跟踪用的 `EASE_RATE = 40`——那个衰减太快（约 25ms），看不出「余势」。继承值本就被 `MAX_TURN_RATE` 钳过、只会越来越小，无需再钳；滑行写 pitch 时仍按 `PITCH_LIMIT` 钳制（与手瞄同界）。

**宽限（不对称迟滞）**：失去可见必须**连续满 0.1s（6 帧）**才真的进入滑行；这 0.1s 内重新出现就继续跟枪。恢复可见**即时**、无惩罚停顿。这 0.1s 内准星仍锁在掩体后的 bot 身上、但**不开火**——开火门控 = **「可见 ∧ 到位」**，宽限期只表示「别急着判它消失」，绝不等于「当它还看得见」。接受这 0.1s 的「隔墙锁」：宽限的全部价值就是「别对一帧遮挡抽手」，若宽限期内冻结，贴掩体边缘会退化成「冻结 ↔ 滑行」来回抖、反而更假；且 0.1s 是肉眼不可分辨的量级。若嫌不适，把宽限调成 0 即回到「即时滑行」（一个常量的事）。

**优先级与边界**：死亡 > 看不见 > 看得见。死亡时宽限计时器**清零丢弃**，重生后从零重新计。滑行只写 yaw/pitch，与开镜 / 切换武器 / 移动 / 蹲滑铲**零交互**（锁定点口径不随 FOV 变）；滑行中途 bot 死亡 → 立刻切冻结（死亡优先）。

**参数全硬编码**（同 ADR-0033 口径，不进「设置」面板——它是演示手感不是训练参数）：宽限 0.1s、衰减 10 /s。可见性判定掩码 = `WORLD_LAYER | BOT_LAYER`、排除玩家自身（与既有 `_bot_has_sight` 同构、方向相反）。结构沿用**纯逻辑类 `DemoAim`**（三态切换 + 滑行衰减数学，GUT 可测，ADR-0009 / ADR-0013）+ 场景层每物理帧一次遮挡射线。

_考虑过把「不在画面 / FOV」也算不可见——会在相机甩向 bot 的途中掐掉追踪，死锁。考虑过用多点采样（躯干/头/脚任一通畅即「部分可见」）——半身掩体后会锁躯干、开火全打掩体。考虑过死亡也加惯性——用户裁定：人类高手会预判死亡、直接停住，且收枪停在击杀点读起来是「稳稳收枪」而非「抽手」。考虑过双向迟滞（恢复也延迟）——会推迟「重新拉枪」，与要的观感矛盾。考虑过线性角减速——与本作其它镜头缓动（指数）不一致，平白多一种手感。考虑过宽限期也冻结（只在满 0.1s 后才动）——边缘抖动会退化成冻结 ↔ 滑行跳变。考虑过把参数进设置面板——它是演示手感不是训练参数，进面板会污染「预设」的职责。_
