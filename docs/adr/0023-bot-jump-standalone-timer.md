# bot 跳跃用独立随机计时器，不绑变向与受击

给 bot 加平地对枪随机跳跃。核心决策：跳跃由 bot 自带的**独立间隔计时器**驱动——每轮在 `[min, max]` 秒窗口内随机等待，到点起跳并重抽下一轮间隔——**不**附加在任何既有操作上。

理由：候选触发点有三个——受击躲避翻向、自然变向、独立计时。绑变向或受击，跳跃就几乎必然与转向同时出现；但实战里对方是**按住一个方向键的中途**起跳，跳跃与变向是两件独立的事。绑受击还有更致命的问题：频率被玩家命中率绑架——玩家练甩枪打不中，bot 就永远不跳，训练越差目标越呆，与训练器的目的相反。

配套决策：

- **门控三件套**：仅地面、非滑铲、视线通畅。
  - 仅地面是技术必然：空中发 `jump` 信号会在 `MovementSimulator` 里锁存到落地（`_pending_jump` 不清），落地瞬间违反意愿地跳。_（2026-10-09 修订：实测发现该「违反意愿」恰是想要的 bhop 语义——空中到点由作废改锁存，落地瞬间起跳，见 ADR-0024。）_
  - 非滑铲：滑铲中的跳跃归「铲跳」管，两套并存会double触发。
  - 视线通畅：视线被挡时跳是浪费频率配额，且会让间隔旋钮失真（设 4–12 秒实际远看不到）。
  - 到点不满足即本轮作废、立即重抽下一轮间隔，**不排队等待**。「刷新」时重抽首跳间隔（与躲避计时同模式）。
- **空中零特判**：开火照常（命中骰照掷、不衰减）、躲避翻向照常（空中 6 rad/s 慢转向天然就是「跳起变向笨拙」的真实感）、落地无特殊处理、表现复用铲跳的 `jump_height()` 抬升路径（视觉模型/命中体/枪口一起升空）。实现 = 一帧 `jump` 信号 + 门控，其余全交现有管线——位移、开火、表现都不另起分支。
- **不与「bot 开镜」互锁**：bot 开镜无视觉表现（只是移速封顶变慢），空中开镜不矛盾；滑铲互锁是因为躺姿滑行举镜画面穿帮，跳跃没有这个问题。
- **跳跃骰用独立 RNG**：学躲避控制 `avoid_rng` 的种子派生模式，不污染开火/滑铲随机序列——固定种子测试不连锁改。
- **开关关闭时计时器冻结**（重开后从原值继续倒数）；间隔窗口倒挂（min > max）在消费端归一为 min..max——两条滑条独立可设出倒挂，与其报错不如按区间语义处理。
- **间隔滑条下限 0.5 秒是故意的**：滞空约 0.72 秒（286 初速 / 790 重力），把间隔窗口压进滞空时间以下就得到落地即跳的连跳 bot——低配跳跳乐是用户可选项，不是 bug。默认 4–12 秒是「时不时跳」的点缀频率，实测定稿后照例可改。
- **预设扩容**：跳跃 3 项（开关 / 间隔下限 / 间隔上限）进预设，23 → 26 项；老预设缺项按默认补齐。

_考虑过附加在变向节拍上（零新增计时器，跳跃与转向同帧最像真人假动作）——被否决：跳跃会几乎只在转向瞬间出现，与实战观察不符；且三档横移间隔不一（0.2–1.0s），单一概率在不同模式下的绝对频率漂移。考虑过受击跳——被否决：频率被命中率绑架。考虑过到点不满足门控时排队等待到条件满足——拒绝：视线长期被挡时跳机会积压，恢复视野瞬间违和地连跳；作废重抽语义更简单也更诚实。_
