# 全屏宽高比：F11 按档位算分辨率、驱动拉伸铺满

玩家要 CS/Apex 的 stretched resolution 观感：16:10 内容横向拉伸铺满 16:9 面板，东西看着「扁」。决策：设置面板「画面与输入」页新增「全屏宽高比」设置项（16:9 默认 / 16:10），**只作用于 F11 独占全屏**——进入全屏时取屏幕高为分母、按所选比例算出宽度（16:10 宽 = 高 × 1.6，通常窄于屏幕；16:9 宽 = 高 × 16/9，恰为桌面原生，与旧行为数值等价），`window.size` 设为该值再进 `MODE_EXCLUSIVE_FULLSCREEN`，Windows 切换显示模式后由 GPU 驱动整体拉伸铺满。拉伸对 3D 与 UI 一体生效；相机 `keep_height` 现状不动——竖直 FOV 恒定、水平 FOV 随比例收窄再被拉宽，正是 CS stretched 的语义（2026-10-12 拷问会话定稿，七项全按推荐）。

## 修订 ADR-0019 的边界

ADR-0019 定下「F11 不进设置面板、不持久化」——指的是全屏**状态**。本次在其上正交新增宽高比**设置项**：进「画面与输入」页、持久化（settings.cfg `[video]` 段 `aspect`，9/10，默认 9）、不进「预设」。F11 本身仍是会话级热键，全屏状态照旧不持久化、每次启动回窗口模式。

## Considered Options

- **引擎内拉伸**（主场景渲到 16:10 SubViewport 再拉伸 blit）：不依赖驱动缩放设置，但主渲染管线大改——武器视角、曳光重投影、FX 采样全要重接，成本高一个量级，否决。
- **锁水平 FOV**：竖直视野随比例增多，不是 CS 的语义，否决。
- **窗口化也套用比例**：窗口自由缩放本就是现状，拉伸只在独占全屏下有意义，否决。
- **分辨率设置独立成页**：单设置项占一个页签太空，并入「画面与输入」页 + 只读信息行（如 `2560×1440 → 2304×1440（拉伸）`）。

## Consequences

- **依赖驱动缩放为「全屏」**：N 卡控制面板缩放默认「纵横比」时 16:10 档两侧出黑边而非拉伸——与 CS 同源的前提，属用户侧一次性设置，不为它换架构。
- **切换时机**：全屏状态下于设置页切档立即重设分辨率生效；窗口化仅记录、下次 F11 生效；退回窗口化恢复进全屏前的窗口尺寸。
- 16:10 档水平视野比 16:9 窄是**观感设计本体**（水平收窄 + 横向拉宽 = 目变胖变扁），不是缺陷。
