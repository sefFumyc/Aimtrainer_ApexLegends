# 受击红屏二轮：全屏泛红改边缘红晕（修订 ADR-0019）

ADR-0019 定稿的全屏泛红实测暴露一个观感问题：**整个屏幕一起红太晃眼**——反馈的「清晰可感」被「刺眼」抵消，且全屏覆盖直接压住视野中央的战斗信息。

定稿方案（拷问定案，2026-10-04）：

- **形态 = 径向红晕（vignette）**：以屏幕中心为圆心的椭圆渐变，中心完全透明、往边缘越来越红、四角最浓。FPS 受击反馈的标准做法，四周任何方向受击观感一致，天然匹配宽屏（左右覆盖多于上下）。
- **空区多、红带窄**：用户明确要求「留空区域多一点，边缘红区域少一点」——渐变带从距中心约 75% 半径处才开始起色，红带只占最外约 25%。调参起点，实测可调。
- **峰值保持 0.32 不补偿**：用户选择继续含蓄路线，先看边缘化后的观感；嫌存在感不足再提是一行改动。
- **时序与开关零改动**：`HitFlashTiming` 纯逻辑类（线性渐隐 0.4s、重复受击刷新）、`hit_flash_enabled` fx 段开关、CONTEXT 术语名「受击红屏」全部原样保留——本轮只改 alpha 的**空间分布**，不改时间分布，纯场景层 `_draw_hurt_flash` 重写。

_考虑过四边矩形渐变条带（边框式）——否决：条带内缘有可见分界线，且宽屏下左右条与上下条观感割裂。考虑过边缘化后把峰值提到 0.5 补偿存在感——用户否决：先看边缘化后的观感，继续含蓄。全屏泛红方案本身（ADR-0019 原案）——废止，理由见上。_
