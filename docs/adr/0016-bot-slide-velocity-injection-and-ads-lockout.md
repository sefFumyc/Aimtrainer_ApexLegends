# bot 滑铲用速度直接注入（跳过疾跑前摇与蹲键），并与 bot 开镜互锁

票 09 给 bot 加「攻击滑铲」「重生滑铲」「铲跳」三个动作。核心矛盾：移动模型（ADR-0002）里「滑铲」的触发链是**疾跑满速 + 按蹲 + 速度 >200**，这套链对 bot 有两个致命问题：

1. **前摇暴露**：bot 要先疾跑半秒才能滑，玩家在这半秒里能白打高额伤害；且疾跑要求前向输入，bot 期间无法保持朝向玩家，压不住火力——压迫感全无。
2. **蹲键依赖**：滑铲维持条件是「按住蹲」，而 bot 的输入装配里根本没有蹲键（`_ctl_crouch` 恒 false），自然触发的滑铲当帧就被「松开蹲」掐断。

定稿：给 `MovementSimulator` 加 `start_slide(dir, speed)`，**直接注入**满速滑铲初速（399 u/s，与玩家满速持枪滑铲初速一致）并置 `_slide_auto` 标志——滑行维持不依赖蹲键；`end_slide()` 供 bot 在随机时刻站起。注入滑铲与玩家滑铲共用同一套减速、铲跳倍率与状态机，不另起一套物理。

配套决策：

- **滑铲期间冻结躲避与探测**：滑行方向固定（零输入直线），`AvoidanceController` 的翻向/变向全部暂停，但开火照常（朝向仍指向玩家，回头射击）；滑铲结束（站起 / 铲跳升空 / 滑完）后恢复。
- **与「bot 开镜」互锁**：开镜封速 130 < 滑铲门槛 200，两者同开会把注入滑铲废掉。规则：任一滑铲开关开启时 bot 开镜失效（设置页置灰 + 自动取消，感知层同一道保险）。
- **动画回落**：KayKit Adventurers 没有 Crouch / Slide 动作（GLB 内动画名已核），滑铲表现 = 命中体按蹲伏进度整体压低 30u；若日后换带 Crouch 动作的模型，动画层自动接管（`target.gd` 按模型是否含该动作分支）。
- **预设扩容**：滑铲 4 项（攻击滑铲 / 重生滑铲 / 铲跳 / 铲跳概率）进预设，19 → 23 项；老预设缺项按默认补齐。

_考虑过让 bot 走正常触发链（先疾跑再蹲）——被玩家否决：前摇半秒纯属白挨打，且背对玩家滑出完全丧失压迫感。考虑过把滑铲维持改成「蹲键 OR 注入态」以外的第三套状态机——拒绝：两套滑铲物理必然漂移，回归测试翻倍。考虑过 ADS 与滑铲可以共存（开镜只影响开火精度）——但开镜封速会直接掐死滑铲触发条件，共存是假象，互锁是诚实选项。_
