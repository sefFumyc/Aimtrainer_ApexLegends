# FX 按渲染位姿采样 + 开镜火光只留照亮

开火特效（枪口火光、曳光弹）原先在物理帧内采样枪口世界坐标，而相机位姿（`_tick_move`/`_tick_zoom`）在采样**之后**才更新、枪体后坐恢复更是在渲染帧 `_process` 才应用——玩家转身或开火时，特效系统性滞后一个物理帧、再差一次 kick 偏移，与所见枪口脱节。bot 侧经核查**无此问题**：`target._apply_pose` 在物理帧内以 MANUAL 模式推进动画并 `_sync_gun`，特效采样即是渲染位姿。决策两条：

1. **一切开火特效按本帧渲染位姿采样**：玩家侧分两步——① `_tick_weapon`（开火结算）排到 `_physics_process` 里相机更新（`_tick_move`/`_tick_zoom`）之后，开火帧只记命中终点；② 特效播放延迟到 viewmodel 的 `pose_applied` 信号（`_process` 里后坐恢复已应用、枪体 rig 定稿之后）再采样枪口，起点与本帧渲染枪口逐像素重合；火光与光源在存活期内**每帧跟随枪口**（转身时火光是枪的一部分）。曳光保持世界锚定（弹道语义），只在落位时采样一次起点。bot 侧无需改动。命中结算与弹道口径**不变**，仍留在物理帧（视觉采样口径与游戏逻辑口径是两件事）。
2. **开镜时玩家火光只留照亮、不显示体积**：火光球尺寸随「开镜进度」×(1 − p) 收敛到零，点光源（OmniLight）保持满幅——满开镜时枪口只照亮场景，不再有糊在准星上的大块发光球（半径 4、emission 6 的球正对屏幕中心，实测晃眼）。bot 火光与曳光弹都不收敛：前者在远处不晃眼、后者是弹道反馈信息。

## Considered Options

- 火光体积超阈值直接隐藏（zoom_p > 0.5）：有可见跳变，否决；平滑收敛与「滑铲镜头动态」（票 07）同款曲线。
- 点光源能量同步衰减：丢掉开镜时的战场照亮反馈，否决——用户明确要「只照亮」。
- 曳光弹同步减淡：丢弹道信息，否决。
- 只调 `_physics_process` 顺序、不动 kick 注入时机：开火帧仍会差一次 kick 偏移（枪已踢开、特效钉在踢之前的枪口），连发时肉眼可见，否决。

## Consequences

- `_physics_process` 内的顺序约定从「输入 → 开火 → 移动」变为「输入 → 移动 → 开火」——后续调整物理帧顺序时**不得**把开火挪回相机更新之前，否则滞后回归。
- 玩家特效落位依赖 viewmodel 的 `pose_applied` 信号：其时序成立的前提是 `_process` 树序（main → player → viewmodel，父先于子）——若信号改为轮询或调整场景树层级，需重新核对采样时序。
- 后坐踢动（相机 kick）在开火后的下一物理帧才上屏，滞后 ≤16ms，实测不可感知。
- 特效采样口径（渲染位姿）与弹道口径（逻辑朝向）从此显式分离，与 ADR-0008「逻辑瞄准与渲染相机分离」一脉相承。

## 二轮修订（2026-10-05：起点口径 = 枪管轴线 + 开镜 FOV 差补偿）

一轮落地后用户实测：曳光弹不像从枪口出来，而是「枪口上面」。两层根因：

1. **起点骑在枪顶**：`_fit_model` 把模型顶面压到 y = 0，一轮的枪口本地坐标 `(0, 0, −len)` 取的是**枪体顶面前角**，不是枪管轴线——火光是半径 4 的大球看不出来，曳光是细线，起点明显高于枪口孔位几十像素。
2. **开镜 FOV 差**：开镜只缩主相机（92.35 → 76.64），武器相机恒 92.35——同一个 3D 点在两个世界投影到不同屏幕位置（缩放差放大离轴偏移），满开镜残留 ~25px 反向偏移。

修订决策：

- **起点改枪管轴线**：每枪一个「枪管高度系数」（模型拟合后高度 × 系数），截图探针（枪口平面上不同高度打标记球）两轮校准定稿（粗探定范围、精探 0.03 步进加密）：步枪 0.36、手枪 0.34；程序化兜底枪枪管就在 y = 0，无需系数。
- **FOV 差补偿**：`player.muzzle_world()` 把武器相机看到的枪口点按其屏幕位置用主相机在**同深度**重投影——两相机 FOV 相等时数学上退化为恒等，腰射 / 开镜 / 滑铲 FOV 微扩全状态逐像素重合；纯数学 ~10 行，抽在纯逻辑类 `MuzzleReproject`（GUT 可测），调用方（main 的火光与曳光）无感。
- **bot 侧**：`MUZZLE_HEIGHT = 45` 本是视线判定口径，探针核查与枪口视觉高度偏差 ≤5u 则不动。**实际结局**：数值探针实测枪口视觉高度 ≈26.6–27.6u，偏差 −17.4~−18.4u 超阈值——在枪上加 Muzzle 标记（`muzzle_world_visual` 优先读它，随 `_sync_gun` 逐帧跟随），特效起点落到枪管轴线；**视线判定口径不变**（ADR-0018：bot 决策零改动）。

新增否决项：

- 只降起点、不补 FOV 差：腰射完美，满开镜残留反向 ~25px「从枪口下面出来」，否决。
- 武器相机 FOV 跟随开镜缩放：真逐像素且实现最简，但满开镜枪模放大 ~32%，推翻已定稿的 `ADS_Z = −8`「推远到不糊脸」观感，否决。

新增 Consequences：

- `player.muzzle_world()` 返回的是**补偿后的起点**，与武器世界里的枪口点不再严格同点（只在 FOV 有差时偏离，同深度）；改 `_fit_model` 拟合逻辑时枪管系数必须重新校准。
- bot 的视线判定起点（`muzzle_world`，地面 + 45u）与特效起点（`muzzle_world_visual`，枪上标记）从此显式分离：改持枪姿态 / `_sync_gun` 只影响视觉起点，判定口径不受牵连；两个枪管系数（玩家 `Viewmodel.RIFLE_BORE_FRAC` 与 bot 共用）必须保持同源引用，换枪模时一起重校。

## 三轮修订（2026-10-05：曳光存活期起点跟随，推翻一轮「世界锚定」）

二轮落地后用户实测：静止开火已逐像素重合，但**转向与移动中开火**曳光仍明显脱节——一轮决策「曳光保持世界锚定（弹道语义），只在落位时采样一次起点」在运动场景下必然如此：静止长线同时占据起点（贴枪）与终点（弹着点），玩家在 0.1s 存活期内疾跑位移 ~30u、转头扫弧 ~4u，起点与枪口必然分离。落位帧的修复没有错，错的是「存活期不动」。

修订决策（方案 A「线绑枪」，拷问定稿）：

- **曳光起点存活期逐帧跟随当前枪口**（玩家 `muzzle_world()` / bot `muzzle_world_visual()`，与火光/光源同款「开火特效是枪的一部分」口径），**终点钉在落位时的弹着点不动**（弹着点是世界里的反馈信息，不跟枪）——起点动终点不动，方向与线长每帧重算。
- 已知代价（定稿时接受）：开火后立刻大幅转身，曳光呈现「从新枪口拉向旧弹着点」的歪线，最多存在 `TRACER_LIFE` = 0.1s，线指向不再严格是开火瞬间的射向。「弹道语义」让位给「起点永远从枪口出来」的用户实测观感。

否决项：

- 飞行弹段（弹丸式，短亮条沿弹道飞向终点）：最像真 FPS、「起点脱节」直接不存在，但视觉形态大改（长线 → 飞行段）、不再显示完整弹道，工程与调校量级更高——留作后续观感仍不满意时的升级路径。
- 缩短存活期（0.1s → 0.05s）：脱节窗口减半但疾跑仍偏 ~15u，治标，否决。

新增 Consequences：

- 曳光在存活期内不再严格表示「开火瞬间的弹道线」，而是「枪口到弹着点的动态连线」；若未来有引用曳光做弹道分析的场景，需另行采样落位帧数据。
- bot 侧与玩家侧同款跟随（统一走特效每帧落位路径），bot 曳光起点每帧取 `_sync_gun` 之后的枪上标记。

## 四轮修订（2026-10-05：终点两端绑定，扩展三轮「终点钉死」）

三轮落地后用户实测：起点不偏了，但**落点偏**——移动/转身时线远端「没跟上」。根因与三轮对称：终点钉在落位帧的世界坐标，而它的参照物在动——命中 bot 时 bot 在 0.1s 存活期内横移 ~17u，线远端钉在开火瞬间的命中点、bot 已走开，线落在空气里；bot 打玩家的曳光终点钉玩家当时位置，玩家跑开线端留在原地；大转身的歪线代价（三轮已接受）同时被放大。

修订决策（方案 B「两端绑定」，拷问定稿）：

- **曳光 = 发射者枪口到命中处之间的动态连线，两端各绑各的实体**：起点逐帧跟随发射者枪口（三轮已做）；终点分三种——**命中 bot**：命中点转存**命中体局部坐标**、每帧换算回世界（bot 平移/转向/躺姿压深/铲跳升空全部跟随，命中反馈始终贴在 bot 身上被打中的点）；**bot 打玩家**：每帧取玩家当前位置（`BOT_TRACER_HEIGHT` 口径不变）；**未命中**（200u 空气/遮挡点）：世界钉死（无参照物，钉哪都一样）。
- 实现细节：bot 死亡/撤下时玩家命中型曳光**整条冻结**（命中体重位前不再跟随，防 respawn 瞬间线端飞到新刷新点；死亡后 respawn 倒计时 ≥1s，0.1s 曳光寿命内不会撞上）。

否决项：

- 飞行弹段（三轮已否，仍留观感仍不满意时的升级路径）。
- 只修终点、起点回到世界锚定（拆开处理）：两端参照物都在动，只修一端必剩另一端，否决。

新增 Consequences：

- 曳光在存活期内的语义完全动态化：「谁的枪 → 打中谁身上的哪一点」；曳光不再可用于回放开火瞬间的弹道几何（需另行采样落位帧数据）。
- 命中点跟随挂在命中体上：改命中体的压深/升空挂载方式（`SLIDE_SINK` / lift）时需复核曳光终点跟随。

## 五轮修订（2026-10-05：废弃静态长线框架，转飞行弹段）

四轮落地后用户实测仍不对：「往右走，曳光终点在我触发的左边，给人一种子弹飞行速度很慢的感觉」。复盘确认这不是绑定 bug（impact 是开火物理帧的正确命中点），而是**静态长线框架本身与快速移动的第一人称不兼容**：静止长线 = 「已到达、停在那儿的弹道驻留」，玩家开火后继续移动，准星指的点持续随视线平移，钉死的弹道两端相对准星持续滑动——三轮修起点（跟枪）、四轮修终点（绑命中体），但只要线是「静态连线」，移动中它必然与当前视线错位，「慢弹道」观感是框架的固有属性，不是端点绑定的实现缺陷。

修订决策（方案 D「飞行弹段」，拷问定稿）：

- **曳光 = 高速飞行的弹丸短亮条**：开火瞬间从枪口（落位帧渲染位姿枪口）发出 ~12u 短亮条，沿弹道方向 0.1s 内飞完全程（速度 = 弹道长 ÷ 0.1），到达即消失——「飞行中的弹丸」而非「驻留的弹道」。
- **弹段出膛后钉死弹道**：不跟枪、不跟发射者（子弹出膛后不受发射者移动/转身影响，物理正确）——三轮的「起点跟枪」随静态长线一并废弃。
- **命中 bot 时弹段微转向**：终点每帧从命中体局部坐标换算（`tracer_hit_local` / `tracer_hit_world` 保留自四轮），bot 走了弹段追着飞到它身上；未命中/遮挡沿直线飞到视线 200u 或遮挡点（四轮口径不变）。
- 玩家与 bot 两侧同构（bot 侧起点 = 落位帧枪上标记，同样出膛钉死）。

否决项：

- 继续修补静态长线（更短寿命 / 更快淡出）：错位减半但仍存在，治标。
- 弹段全程跟随枪口：弹丸不是枪的一部分，跟随反而引入新的「甩线」。

新增 Consequences：

- 「曳光」一词在本仓库的语义 = 飞行弹段（弹丸观感），不再是「弹道亮线」；`TRACER_LIFE` 仍为飞行全程时长（0.1s），段长为独立表现参数。
- 静态长线时代的「起点跟随/终点绑定」逻辑移除，命中体局部换算（四轮引入）保留用于弹段终点微转向。
