# 项目结构：场景化 + 纯逻辑类分离 + Autoload 设置单例

原版是纯代码构建的三维场景。Godot 版改为三层：实体与组件用编辑器可见的场景（Player / Bot / Arena / HUD / Main 等 `.tscn`）；可移植的纯逻辑（移动积分、躲避控制、单发缓冲、计时器、对局统计）写成**不依赖节点树**的纯逻辑类，由场景调用；全局设置用 Autoload 单例承载，持久化到用户目录的配置文件（替代原版的 localStorage）。

理由：纯逻辑不依赖节点树，才能与原实现保持同构、也才可能被单独验证；节点树用场景表达才符合 Godot 习惯，也才让这个仓库能当模板复用。

_否决「全代码运行时构建节点」：失去编辑器可视化，模板价值下降。否决「目录完全镜像原版 TS 结构」：会把网页时代的模块边界带进引擎项目。_
