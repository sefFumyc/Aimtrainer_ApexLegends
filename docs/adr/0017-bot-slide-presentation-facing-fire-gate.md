# bot 滑铲表现：坐姿动画 + 朝向「转向滑行方向再回头」+ 瞄住开火（修订 ADR-0016）

票 09 首版实测暴露三个问题：

1. **滑铲不可读**：Knight.glb 没有滑铲/蹲伏类动作在用，模型保持站立跑姿以 399 u/s 滑出——玩家只看到「莫名其妙的加速」，没有滑铲的形体语言。
2. **铲跳完全失效**：设置页三个滑铲开关的互锁回调 `_sync_slide_interlock()` 被 `_bound_check` 以「勾选状态 bool」为实参调用（`extra.call(v)`），而该函数不收参数——Godot 对参数数量不匹配抛运行时错误并中断回调。结果：勾滑铲开关时互锁刷新中断，铲跳勾选框卡死在置灰、概率滑条行永不显示，用户根本无法启用铲跳。修复 = 给互锁函数加可选参数收下回调实参。
3. **朝向规则修订**：首版「滑铲中朝向始终指向玩家、回头射击」观感是「站着平移打枪」。用户修订为：起步先转向「滑行方向」（约 0.1s），滑行中按固定角速度（360°/s）转回玩家，转至夹角 ≤10° 视为「瞄住」并恢复开火——转身耗时天然成为玩家的安全输出窗口，瞄住后哪怕还在滑也开火（起身不锁移速、纯表现）。

定稿方案：

- **滑铲姿势 = 模型自带 `Sit_Floor_Down / Sit_Floor_Idle / Sit_Floor_StandUp` 三件套**：滑铲瞬间坐倒 → 坐姿滑行 → 站起回正常走跑。事实依据：Knight.glb 的动画库远超 `CLIPS` 表在用范围，`Lie_Down/Lie_StandUp`（平躺）与 `Sit_Floor_*`（坐地）都是现成的；用户在两者间选了坐地（更接近滑铲的矮姿观感）。
- **命中体维持 −30u 下沉**（与蹲伏共用 `CROUCH_HEIGHT`）：坐姿视觉高度 ≈ 35–40u，与 72−30=42 的判定轮廓基本吻合；没有明显旋转轴，不做旋转跟随。
- **铲跳空中姿势**：跳起后从坐姿**平滑过渡**（blend，非瞬间切换）到正常跳跃动作、落地回站立——「不松蹲」是移动层语义（继承滑铲方向、空气摩擦），姿势层按用户要求回正。
- **朝向实现落点**：`BotAi.update` 的滑铲分支不再每帧 `set_facing(玩家)`，改为滑铲状态机驱动朝向目标（先滑行方向后玩家）+ 角速度收敛；开火闸 = 朝向与玩家方向夹角 ≤10°，未瞄住时 `_update_firing` 静默。

_考虑过 Lie_Down 平躺方案（辨识度更高）——用户选了 Sit_Floor：躺平在训练场景里过于夸张、且持枪手仰躺观感怪异。考虑过起身僵直（起身动画期间限速）——否决：与「滑铲无前摇」的压迫感哲学相反，等于给玩家白送输出窗口。考虑过滑铲期间完全停火——用户定稿为「瞄住即开火」：转身时间已经是窗口，无需额外惩罚。角速度 360°/s 与对齐容差 10° 是手感调参起点，可实测后调。_
