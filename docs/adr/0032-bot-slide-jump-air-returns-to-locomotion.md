# bot 滑铲表现三轮：铲跳空中交回常规动作（修订 ADR-0018）

用户实测反馈：把 bot 跳跃间隔压成连跳参数、且 bot 由滑铲起跳（铲跳）时，空中姿势「像 T-pose」——细看是**完全不动**；而 bot 由走路起跳（普通跳）时表现正常，用户明确以普通跳为「正常跳跃动画」的基准。

排查坐实的根因（全部代码级证据）：

1. **连跳链里 sim 从不呈现地面态**：`movement.gd` 的落地子步只清 `_airborne`、不动 `_state`；连跳的落地帧立即起跳（票 12 的 bhop 锁存），`_step_ground` 的跳跃分支又把 `_state` 写回 `"airborne"` → 整条 bhop 链 `ai.sim.state()` **恒为 `"airborne"`**（语义正确：连跳链确实没有地面帧，`airborne()` 同款）。
2. **`SlidePose.AIR` 的退出条件正是 `state != "airborne"`** → 在连跳链里**永续**；它返回的 `Jump_Idle` 是一支 1.07s / 33 帧的**近静止**循环（glTF 剖析 + FK 探针：整支动作里手骨相对胸骨位移仅 ~0.1–0.3 单位，而臂展本身 ~1.2–1.5）→ 模型停在「张臂平衡姿」近乎不动 = 用户看到的「完全不动」。
3. **非连跳时落地后 `state` 回地面态、AIR 当帧退出** → 回常规走/跑动作 → 看起来正常。这解释了「只有连跳参数 + 铲跳起手才复现」，也解释了普通跳为什么正常。

定稿方案：

- **铲跳空中不再持有任何专用动作**：删 `SlidePose.RISE` / `AIR` 两个状态与 `CLIP_JUMP_START` / `CLIP_JUMP_IDLE` 两个常量；`SlidePose.DOWN` / `LIE` 遇 `state == "airborne"`（按构造即铲跳）直接回 `NONE` 并返回空串 → 常规走/跑动作立即接管，躺→跑只靠 `frame.blend`（200/250ms）交叉淡化。
- **与普通跳对齐**：普通跳本就「空中零特判」（ADR-0023），空中播走/跑动作；铲跳从此与它走同一条路径——用户以普通跳为「正常」基准，这是唯一被用户认可的形态。
- **删除 `_jump_pose_clips` 自检与 `Jump_Idle` 的 `LOOP_LINEAR` 设置**：不再有任何跳跃 clip 参与滑铲表现，防御分支失去意义（「模型缺动画」的兜底仍由 `_slide_pose_clips` 承担）。
- **纯表现层**：`bot_ai.gd` 的滑铲/铲跳决策与 `movement.gd` 移动模型零改动；姿势机在场景脚本里、不在测试缝上。
- **域文档与回归网**：`CONTEXT.md`「铲跳」词条删去「跳起后姿势平滑过渡回正常跳跃」（词条本不该含实现细节，且该措辞随本 ADR 失效），并校订 `target.gd` 三处过期注释（常量注释的「跳跃两件套」、命中体注释的「已过渡回跳跃站姿」、姿势机调用点的动作清单）；`tests/unit/test_movement.gd` 补 `test_bhop_chain_has_no_ground_state_frames`，把根因前提（连跳链无地面态帧）钉成可复跑的回归网——姿势机不可测，`MovementSimulator.state()` 的口径是它唯一的可测依赖。

_考虑过换一支跳跃 clip（`Jump_Full_Short`，1.17s 一次性）——否决：在永续空中的连跳链里会播完并**定格末帧**，比现状更糟，也说明问题不在「哪支 clip」而在「空中不该持有专用 clip」。考虑过保留 `Jump_Start` 一次性过渡（0.6s）后交回常规——否决：动作有界不会冻，但 0.72s 的空中前 0.6s 仍是张臂跳跃姿，且躺→跳姿本身要一次 snap（`Jump_Start` 首帧已近站姿），过渡收益与占比不成比例。考虑过用 `Lie_StandUp` 快放做起身过渡——否决：过渡最顺（末帧即站姿），但「躺着起身」在空中语义错且占满空中。考虑过给 AIR 留「防御性回退」——否决：AIR 正是本次 bug 的载体，留着等于把坑留在原地。_

**验收（实测）**：
1. **根因前提**：`MovementSimulator` 纯逻辑直驱（跑满起跳 + 落地帧同帧起跳，仿真 900 帧）测得 `state()` 分布 `{sprinting: 46, airborne: 854}`——首次升空后**地面帧 0 帧、连续 854 帧 `airborne`**，坐实「连跳链里 `state` 恒为 `airborne`」。同口径已落为 `tests/unit/test_movement.gd::test_bhop_chain_has_no_ground_state_frames`（`godot --headless -s addons/gut/gut_cmdln.gd` 可复跑），初版的一次性 `-s` 探针脚本验证后已删。
2. **修后静态枚举**：姿势机在 `state == "airborne"` 下不再有任何分支返回**跳跃专用** clip，铲跳空中必然由常规走/跑接管（唯一例外是 `SlidePose.UP`，见「已知边界」）。
3. **回归**：`--headless --import` 解析零错误；GUT 全量 **228 tests / 1422 asserts** 全绿（含本条新增用例，既有基线不受影响）。
4. **最终观感**：由用户在「连跳参数 + 铲跳起手」下实测确认。

**已知边界（本次不改）**：`SlidePose.UP`（滑铲结束的站起收尾）若被普通跳打断，空中仍会播完 `Lie_StandUp` 再交回常规——有界（0.93s，不会定格）且不属于铲跳路径，按范围纪律不动；若实测在意再开票。
