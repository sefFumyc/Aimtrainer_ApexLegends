# 朝向侧偏角度从参考实现的 45°/15° 收敛到 30°/10°（经 25°/8°、18°/8° 两轮中间值）

票 04 按 CONTEXT 原定义实现侧偏：骨盆 45°、肩 15°、头 0°，数值照搬参考实现 `render/character.ts`。玩家试玩后反馈「摆动时转身幅度大得离谱，像直接要往侧边跑」。法证结论：KayKit 的五个动作**自身**躯干旋转恒定只有约 5°（动画就是「面朝你、腿往侧迈」），观感全部来自程序侧偏——而骨盆旋转发生在 hips 骨上，**两条腿作为 hips 的子骨会跟着转满 45°**，脚尖斜指移动方向，在 Q 版骑士上读起来就是「起跑预备」。第一轮先把角度收敛到骨盆 25°、肩 8°（头保持 0°），「下身朝移动、上身朝瞄准」的语义不变。定稿评审（票 05 截图二轮）玩家确认拧差梯子正确后仍嫌骨盆偏多，第二轮收敛到骨盆 18°；第三轮（票 05 截图三轮）玩家觉得 18° 又过了头，最终定稿骨盆 30°、肩 10°，CONTEXT.md 的「朝向侧偏」条目已同步。

_考虑过完全去掉侧偏（0°）——横移只剩腿侧迈，看起来像滑步，丢掉「下身朝移动」的拧躯干语义；考虑过 15°——观感改善有限而语义弱化更多；考虑过先不立值、每轮截图迭代——试玩反馈需要一条可回退的明确基准，漂移的中间值没法写进验收条件。25° 是「腿仍指向移动侧但不再像起跑」的起点，后续可在截图评审中微调（同步改本 ADR 与 CONTEXT）。_

## 修正（票 05 评审）：净偏角改为逐帧按世界角强制

票 04 的实现把三个角度当「叠在动画上的增量」（骨盆 +25 叠写、胸腔 −17 / 头 −8 静态反旋）。票 05 侧位截图评审发现拧差梯子随步态相位倒挂（某相位骨盆 −7° 而胸腔 +16°）。探针实测：横移动画自带的骨盆世界角在一个步态周期里约在 −32°~+53° 间摆（本 ADR 早前「动画自身躯干旋转恒定只有约 5°」的结论只对局部骨姿态成立，世界角含 root / hips 动画链的拧转），静态增量与反旋抵不掉这个基座。现改为逐帧按「动画当前姿态 → 期望世界净偏角」插值后反解本地写值：满侧偏时骨盆 / 肩 / 头的世界偏角恒为 30° / 10° / 0°，动画自带的俯仰侧倾与位移保留，侧偏强度 0 时逐笔等价于不写。改的是实现基座（rest 增量 → 动画姿态上的世界角强制），角度只按定稿轮次走 25° → 18° → 30°。
