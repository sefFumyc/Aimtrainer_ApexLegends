# 出厂默认烘焙：玩家实测定稿手感（2026-10）

出厂默认原先沿用参考实现的初值；玩家经设置界面临时调出一套实测定稿手感后只存在于本机 `settings.cfg`——删 cfg / 换机冷启动就回落旧默认，需要重新手调。决策：把 2026-10 实测定稿的设置值**整体烘焙进代码作为出厂默认**——`game_settings.gd` 变量初值与 `PresetStore.DEFAULTS`（预设 23 项）逐项同步修改；具体数值以 CONTEXT.md 词条为准（场地布局=多遮挡、移动模式=动态游走、滑铲全开、目标距离 400、走廊 100、后坐力四通道 1.4/2.0/0.72/2.0、灵敏度鼠标 1.0/手柄 1.3/开镜 ×0.5、计时 40/40/8 等）。与 ADR-0021 同批落地。

## 边界

- **移动模拟常量零改动**：`movement.gd` 里的 Apex 实测值（疾跑/滑铲速度等）一个不碰——本决策是「默认选哪一档」的调整，不是对实测参数的「看起来更合理」式改写，故不属 AGENTS.md 要求的有意偏离记录范畴，但仍立此存照。
- 纯逻辑类 `IntervalTimer` 的回落值（60/20/4）保留原样：真实取值来自 GameSettings，注释已注明。

## Considered Options

- 保留 cfg 作为默认载体：冷启动时 cfg 不存在，新机仍拿旧默认，否决。
- 首启迁移脚本把「推荐值」写进 cfg：多一条隐藏路径，冷启动读到的仍是代码初值，等价于烘焙但更绕，否决。

## Consequences

- `game_settings.gd` 初值与 `PresetStore.DEFAULTS` 是**两份人肉同步的副本**：改任一默认必须两处同改，并跑 `test_preset_and_auto_radius`（里面有 DEFAULTS 一致性断言）。
- 验证方式：删 `user://settings.cfg` 冷启动，逐项核对初值（已执行，29 项全中）。
- 烘焙后删 cfg 无损失：原 cfg 的预设表为空、无活动预设。

## 2026-10-12 第二次烘焙

玩家继续实测后又沉淀出一批新定稿值（冲锋枪相机通道 1.1、体型半径 10、游走 0.55、进攻 0.35、撤退 0.25、走廊 125、躲避概率 0.1/0.25、跳跃间隔 0.6–5.5、RAS 概率 0.5、开关设置改绑 B），按同一决策整体烧入代码默认：`game_settings.gd` 变量初值、`PresetStore.DEFAULTS`、`GamepadBindings.DEFAULTS`（与 project.godot 手写 InputMap 保持双处契约）。自建预设表（「半自动」「连发」）属用户快照，**不烧入**——预设是用户数据不是出厂配置；现存 settings.cfg **不动**——迁移只改代码默认，旧 cfg 的值恰好等于新默认，本机无感，新装机直接得到新出厂值。
