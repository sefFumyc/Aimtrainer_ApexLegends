# 引入 GUT，只在纯逻辑缝上做行为测试

ADR-0011 决定本次交付不写自动化测试。该决定被推翻：现在引入 GUT，在**一个高缝**上做行为测试——不依赖节点树的纯逻辑类。

理由是这条缝几乎不要钱：纯逻辑类（移动积分、躲避控制、单发缓冲、计时器阶段机、对局统计）本来就被设计成不依赖节点树（见 ADR-0009），因此可以脱离场景、渲染与输入设备直接构造与断言。而其中**移动积分最值得测**：它的全部参数是从 Apex 实测值移植来的，任何一处回归都会直接毁掉这个项目的核心资产，而肉眼看曲线是看不出"90° 换向后应该保留 65% 还是 71%"的。

测试只断言**外部行为**（给定控制意图与 dt 序列，断言速度向量轨迹），不断言内部状态字段与私有方法；不测场景装配、渲染、后处理、viewmodel 的 SubViewport 隔离、InputMap 映射、帧率、手感与观感——这些只能实测。

_考虑过沿用原决定（测试由使用者自己的流程承担）：但既然纯逻辑层的接缝是现成的，把移植来的实测数值变成可执行的期望，是防止手感回归的唯一廉价手段。_

**Consequences**: 项目引入 GUT 依赖。ADR-0011 中「文档优先」与「垂直切片」两条决策仍然有效，仅「不写自动化测试」一条被本文取代。
