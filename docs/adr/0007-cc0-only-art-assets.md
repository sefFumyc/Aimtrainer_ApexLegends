# 美术资源全部采用 CC0，否决官方 TPS Demo 资产

Godot **不内置任何游戏美术资产**，也没有内置的「第一人称控制器」项目模板——原版「枪模与 HUD 尽量用引擎自带的」这一设想在美术部分不成立（HUD、后处理、粒子、动画系统等**能力**确实是内建的）。资源因此全部选用 CC0：枪械用 Kenney Blaster Kit（40 个模型，含 GLB，作者明确标注兼容 Godot），角色与动画用 KayKit Adventurers（5 个绑骨角色 + 25 件武器配件 + 免费动画包）。两者都是真 CC0：零署名、零商用限制。

_否决官方 tps-demo 的美术：Asset Library 标它为 MIT，但仓库 LICENSE.md 声明资产为 CC-BY 3.0，两处标注冲突，需署名且以仓库为准。否决 Quaternius：已从 CC0 改为自定的 QAL 许可（免署名，但禁止再分发资产本身）。_

**Consequences**: 第三方资产入库时必须各自附上许可说明文件。只提交**项目实际用到的文件**（筛掉资源包里附带的其他格式版本），其余不进仓库；不使用 Git LFS——理由是这个仓库只有单一使用者与单一工作机，LFS 换来的「历史更瘦」在这里没有价值，而它带来的「clone 方须先装 LFS 插件，否则拿到的是空壳文件」是真实风险。代价是 git 历史会永久变大且无法回收，因此这条是一次性承诺：一旦提交了错误的大文件，改主意也删不掉。

## 修正 (2026-10-02, 票 06)

连发枪从 blaster-e（狙造型）换成同包的 blaster-d（突击步枪造型），玩家 POV 与 bot 手持同步；1x 红点镜在 kit 里没有独立瞄具模型，改为程序化（开框式：两侧细柱 + 发光红点，按 Apex 1x 点镜样式，开镜不挡视野）。手枪 blaster-k 不变。

实测教训：**Kenney blaster-kit 的 GLB 导入 Godot 后 +Z 端是枪口**（blaster-d / blaster-k 两端端面渲染实锤），与挂点「−Z 朝前」约定相反。两处挂枪的适配方式不同：POV 侧在 `_fit_model` 里把模型绕 Y 转 180°（翻转作用于模型子节点，持久生效）；bot 侧 `WEAPON_ROT` 手骨姿态标定（票 05）的合成结果恰好把模型 +Z 端对到角色前方，**无需翻转**——且 `_sync_gun` 每帧覆写枪的全局变换，挂在枪根上的本地翻转活不过一帧（探针实测，曾经 holder 翻转方案验证为死代码后删除）。
