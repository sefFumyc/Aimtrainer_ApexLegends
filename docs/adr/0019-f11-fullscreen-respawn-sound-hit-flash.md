# F11 独占全屏热键、刷新三维音与受击红屏

三件感知反馈 / 显示模式的小补全一起定案（2026-10-03 拷问会话）：互相独立，各自都是一个缺口的最小闭环。

## 决策

### 1. 全屏 = F11 热键，不进设置面板、不持久化

- F11 在「窗口」与「独占全屏」（`DisplayServer.WINDOW_MODE_EXCLUSIVE_FULLSCREEN`）间切换；InputMap 新增 `toggle_fullscreen` 动作，由 main 的热键轮询（`_tick_hotkeys`）处理，任何舞台（菜单 / 对局 / 结算）都可用。
- **不持久化是刻意的**：全屏属会话级临时偏好，settings.cfg 与设置面板都不收；每次启动回窗口模式。词汇表以「全屏热键」独立成条，与「设置」面板划清边界。
- 用户明确指定**独占**全屏（而非无边框 `WINDOW_MODE_FULLSCREEN`）。

### 2. 刷新音 = 第一个三维空间音频（扩展 ADR-0012 的「全平面音」边界）

- ADR-0012 定下「定频资产 + 平面 `AudioStreamPlayer`、音高微差靠 pitch_scale」的体系，五个音全是平面居中音。刷新音打破这一边界：挂 `AudioStreamPlayer3D` 在 bot 刷新点，**方位感本身就是需求本体**——痛点是「bot 复活了但不知道它在哪」。
- 音色 = 下行两音 990→660Hz（240ms），与击杀音的上行两音（660→990）互为镜像对偶：上行 = 杀死（奖励感），下行 = 出现（落定感）。资产走 `tools/gen_audio.gd` 同一管线，新增 `respawn.wav`。
- **每次「刷新」都响**（含每局开始的首次刷新）——同一代码路径零分支；开局 bot 本就刷在面前 ±90° 扇区，响一声顺便确认方位。
- 3D 播放器的衰减参数要保证「目标距离」拉满（800u）时仍可闻——音量收敛靠调参，不引入 2D 保底双播。

### 3. 受击反馈 = 纯红屏，明确不做方向指示器与受击音

- 玩家被 bot 命中时全屏泛红、随即渐隐，重复命中刷新。纯渲染，不碰任何命中判定与血量结算（与「视觉后坐力」「滑铲镜头动态」同构）。
- 与「击中提示」对偶：击中提示 = 打人反馈，红屏 = 被打反馈，两向闭环。
- 开关「受击红屏」进 fx 设置段（与枪口火光 / 曳光弹 / 命中提示同构），不进「预设」。
- **有意拒绝** FPS 常见的受击方向指示器与受击音：bot 曳光弹每发都指向玩家，方向信息已有来源，再加指示器是冗余。用户明确「单红屏就好」。

## 被否决的替代

- _设置面板全屏开关 + 持久化_——用户否决：要的是热键。
- _2D 平面复活提示音_——否决：解决不了「不知道在哪」，方位感是需求本体，不是附带效果。
- _受击三件套（红晕 + 方向弧 + 受击闷响）_——用户否决：曳光弹已承担方向信息，单红屏即可。

## 影响

- settings.cfg `fx` 段新增一键（受击红屏，默认开）；预设 23 项不变。
- 音频体系出现第一个 `AudioStreamPlayer3D`，后续任何「需要方位感」的音效都应走它而非平面播放器。
- CONTEXT.md「刷新」条目原写的「播放三维音效」此前从未实现——本次实现使文档与代码对齐。
