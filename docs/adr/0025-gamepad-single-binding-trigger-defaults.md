# 手柄键位单一绑定模型，默认砍掉 A/B 只留扳机

把手柄键位暴露成设置面板的可改键项。核心决策：每个可改键动作（跳跃 / 蹲 / 开火 / 开镜 / 切枪 / 开关设置）**至多一个手柄绑定**，改键 = 按一个键整体替换，冲突**抢占**（新键自动从旧动作上摘除）；默认集砍掉 A/B——跳跃=RT、蹲=LT、开火=RB、开镜=LB、切枪=Y、开关设置=Back。

理由：单一绑定让「一键一动作」的心智模型成立——改键语义（按一键替换整组）、行显示（单个友好名）、冲突处理（抢占后旧动作清空）三者所见即所得；双路默认集（跳跃=A+RT）在改键后必然坍缩成单键，与其让「A+RT 改成 X 后 RT 静默失效」隐式发生，不如默认就单键、行为永远一致。抢占优于允许重复：同键双动作在输入独占、动作少而清晰的训练器里只会造成「为什么跳跃开火一起触发」的困惑。默认砍 A/B 还有一层顺带收益：CONTEXT.md「空中」「蹲」的既有描述本来就是 Space/RT、Ctrl·C/LT——A/B 双路是代码多出来的走样，这次是对齐文档而非迁就代码。

配套决策：

- **采集含扳机/摇杆轴**：|value| > 0.6 才算有效输入（防轻晃误采）；采集期间吞掉输入事件，防止手柄键顺手触发聚焦中的 UI 控件。取消 = 再点改键按钮或 Esc。
- **键鼠绑定不开放改键**：本次只暴露手柄——键鼠是主输入路径，改键工程量大且无用户诉求；移动/视角走摇杆直读（不入 InputMap），天然无键位可改。
- **持久化走 settings.cfg 新 `[input]` 段**：即改即存、启动时回灌 InputMap；**不进预设**——与灵敏度/计时器同属全局共享，预设只管训练参数。
- **UI 为独立「键位」页签**：6 行（动作名 + 当前键友好名 + 改键按钮）+ 页级「恢复默认手柄键位」；不做单行恢复，被抢占清空的动作也走这条路恢复。

_考虑过保留 A+RT 双路默认、改键才坍缩——被否决：默认行为与改后行为不一致，显示也要退化成「A / RT」复合串。考虑过冲突允许重复或弹提示阻止——被否决：这个项目里同键多动作没有合理用例，阻止的报错交互反而更重。考虑过给 1/2 直选枪、Esc、F11 也补手柄位——被否决：切枪已有 Y 覆盖，Esc/F11 是桌面工具键，放手柄上无意义。_
