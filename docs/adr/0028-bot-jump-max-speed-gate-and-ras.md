# bot 跳跃满速门与 RAS：跳跃钉在满速瞬间

票 13。用户需求两条：① 跳跃加普适条件——必须横向走到当前状态最大速度才跳，到点未满速则稍延迟、到满速时刻再跳；② 新增「RAS 概率」设置项——抽中跳跃的前提下，以该概率把跳跃延迟到「变向之后重新加满速度的瞬间」才起跳（RAS 为 Apex 社区术语：刚从左转向右、速度刚加满再跳）。

背景事实：bot 永不疾跑，当前状态最大速度 = 基础 199.5 ×「速度修正器」（持枪 0.87 ≈ 173.5 / 开镜 0.652 ≈ 130.1 u/s）；90° 翻向后速度保留 65%、以 ≈380 u/s 恢复，翻向到重新满速约 0.2s；空中无加减速——速度模长在滞空期恒定。

决策（拷问三轮定稿）：

- **满速门普适生效，无开关**：跳跃信号仅在速度 ≥ 最大速度（ε=1.0 u/s 容差）时发出；地面到点未满速 → 挂起等满速瞬间跳；**空中到点未满速 → 直接作废重抽**（空中无法加速，等不到；且起跳满速 → 空中模长不变 → 整条 bhop 链逐跳全过门，连跳不受影响）。满速门生效后空中未满速实际**不可达**（地面满速门/挂起保证起跳瞬间必满速、滞空期无加减速模长恒定），该分支是防御性兜底，不设行为测试。
- **RAS 骰**：到点、通过基础门控（非滑铲 + 视线通畅）后掷，用跳跃独立 RNG（`_jump_rng`），**仅当概率 > 0 时消耗**——P=0 时跳跃 RNG 序列与旧版逐发一致。掷中 → 进入 RAS 挂起；未掷中 → 仅走满速门。**只在地面到点掷**：空中到点不掷 RAS 骰——「等变向」在空中不成立（空中钉点翻向会假触发等变向），故空中到点只走满速门判定。
- **RAS 挂起的阶段判定**：掷中瞬间已满速 → 先「等变向」再「等满速」；未满速（恰好处于某次变向恢复期）→ 直接「等满速」——该恢复完成的瞬间恰好就是「变向后满速瞬间」，宽松口径反而精准命中 RAS 语义。
- **变向锚点 = 任何 `avoidance.dir` 符号翻转**（自然变向 / 受击躲避 / 撞墙与前向探测翻向统一），实现上只比对挂起开始时的 dir。等满速阶段中速度再被翻向抖掉则重新爬（条件本身即速度达标）。空中钉点翻向不会出现——挂起中 bot 在地面、还没跳。
- **挂起优先、计时器暂停**：挂起期间跳跃计时器整体冻结（间隔已消费给挂起的跳跃），挂起结束后从冻结值继续倒数——零额外 RNG 消耗（否决「到点作废重抽」：白耗 RNG）。
- **作废与超时**：挂起期间进入滑铲（含攻击滑铲触发）/ 视线被挡 / 死亡 → 作废；「刷新」清挂起；跳跃开关关闭 → 计时器与挂起一并冻结、重开继续；总超时 2.0s 硬编码（覆盖最坏情况：flip_timer 剩余 1.0s + 恢复 0.3s + 余量；墙边反复翻向使等满速不断重置的场景由此兜底）。
- **设置项**：`bot_jump_ras_prob`（cfg `[bot] jump_ras_prob`），默认 0.0 完全向后兼容；UI「躲避与移动」页跳跃分组、滑条 0–1 步进 0.05、跳跃开关关则置灰；进「预设」（26→27 项）。
- **边界**：铲跳（ADR-0016）走滑铲自己的节奏，不经过满速门；满速判定每帧取当前开镜状态的速度修正器，开镜切换自动跟随。

后果：

- 跳跃时机不再纯随机：满速门把到点顺延最多约 0.25s（变向恢复时长），RAS 挂起最多 2s——「跳跃间隔」的实际节奏在 P>0 时部分让位给变向节奏，属有意设计。
- 满速门无条件生效会轻微改变默认行为（到点落在变向恢复期时跳跃顺延），但 RNG 消耗序列不变。
- 锁存 bhop 与满速门数学自洽：链内速度模长恒定，第一次满速起跳后全链免检。

_考虑过 RAS 掷中后主动立刻触发一次翻向再等满速——被否：改为等待自然变向，保持 avoidance 变向节奏与 RNG 序列零偏移，且符合「等那个时刻」而非「制造那个时刻」的用户意图。考虑过锁存跳整体豁免满速门——被否：语义统一为「跳必须是满速跳」，且空中模长不变使豁免并无实际收益。考虑过 RAS 一律等下一次变向（不看掷中瞬间速度）——被否：恢复期直接等满速更短且语义等价。_
