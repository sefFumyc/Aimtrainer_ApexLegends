# 靶的移动碰撞体与命中体分离，受阻翻向加承诺窗口与物理兜底

票 01 把「命中体 = 模型部件盒」直接挂在靶的 `CharacterBody3D` 上，于是它**同时**是靶的移动碰撞体。KayKit 骑士是 T 字绑定姿势，剑与盾横向伸出约 40 单位，靶因此在「多遮挡」布局下被柱角剐住：纯逻辑满速而 `move_and_slide()` 位移归零，原地卡死（验收 3）。根因是**探测射线从身体中心发出，探不到身体边缘已经剐上的柱角**——探测说「前面通畅」，物理说「走不动」。现在把两者分开：**移动**是与玩家同构的胶囊（半径 = 体型半径、高 72），单独占一层且不在任何射线的 mask 里（所以它不是隐形 hitbox）；**命中**仍是模型部件盒，挂在子 `StaticBody3D` 上、只参与射线，「所见即所中」不变。同时受阻翻向补三件事：翻向后 **0.3s 承诺窗口**（两个侧向都被探到受阻时若不设窗口就每帧翻向，每次翻向都重触发「转向衰减」、逐帧相乘把速度抖到近 0），**物理受阻兜底**（纯逻辑满速而物理实际位移不足一半时按同一语义翻向，同样受承诺窗口约束），以及靶的推进从 `_process` 移到 `_physics_process`（`move_and_slide()` 用的是物理帧 delta，混用会让靶的移速随显示刷新率变化）。

_考虑过用「命中体的包围半径」加宽探测射线（中心线两侧各补一条偏移射线）——T 字姿势的包围圆半径约 54，而遮挡物之间的净间隙只有 90，靶会因此永远挤不进任何缝隙、在缝隙口反复翻向。考虑过保留宽的移动体、只靠兜底翻向——撞角时零位移恰好发生在最容易再次撞上的位置，抖动只是被推迟。考虑过引入最简障碍绕行（ADR-0005 的回退方案）——探测与兜底已足够，绕行会让「照搬原版侧移」的语义开始分叉。_
