# 输入层收敛到 Godot InputMap，废弃伴生输入与延迟测量

原版为了绕开浏览器 Gamepad API「随显示器刷新率交付输入」的地板，引入了 C# XInput 伴生进程 + ViGEm 虚拟手柄 + WebSocket 输入源 + Web Worker 主线程隔离，并配套一整套端到端延迟测量（系统采样周期/系统最低延迟/测量口径等）。Godot 的原生输入不经过浏览器交付链路，这套机制的问题前提不存在，因此整条链路与「输入延迟与测量」领域的全部概念一并删除。Godot 侧只用 InputMap + 原生手柄读取。

保留的输入语义：输入独占（有手柄连接时忽略键鼠）、摇杆离散（8 向 + 每轴 13% 死区）、右摇杆 0 死区、开镜灵敏度倍率作用在三条输入路径的统一乘子上。

_代价：失去原版的亚毫秒端到端延迟测量能力。若日后确实需要，应在 Godot 侧用输入打点重建，而不是把伴生进程搬回来。_
